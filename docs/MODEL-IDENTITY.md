# 模型身份与版本核实（2026-11-13）

## 结论

**目前不能确认三个档位的具体底层模型或版本。** `Z.ai / GLM` 是重要线索，但不是定版证明。官方目录和响应元数据只暴露 `chat-pro` / `chat-flagship` / `chat-flash` 别名，不应据此把旗舰写成 GLM-4.6，或把旗舰/极速分别写成 GLM-5.3 / GLM-5.3-Flash。

## 已完成的参考对照

通过本机 Magpie 对三个 TeleAgent 档位与 `GLM-5.3`、`GLM-5.3-Flash` 参考模型执行同一组 10 道题，共 50 次请求，全部 HTTP 200。

短题结果高度相似：特殊字符复制、Python 平方和函数、未知函数 `zq_flux_capacity_v7`、`strawberry` 字母计数、矩阵转置、2 的 10 次方等输出一致或基本一致。该现象只说明**短题行为相似**，不能证明同一底座，也不能证明三档是三个不同底座。

参考通道中，`GLM-5.3` 的准确型号自报为 `GLM-130B`，开发方自报为 `Z.ai, GLM`；`GLM-5.3-Flash` 的准确型号自报为 `GLM`，开发方自报为 `Z.ai, GLM`。这与部分 TeleAgent 回答相似，但**自报本身仍不是版本证明**。

## 为什么不能按自报定版

旗舰档在重复身份题中给出了互相矛盾的版本：

- `GLM-130B`
- `GLM-4-6B`
- `GLM-4.6`
- `GLM-4`
- 另一轮还出现 `Moonshot AI, Kimi` 和“阶跃星辰”

因此，issue #1 中的单次 `GLM-4.6` 只能记录为待核线索，不能作为最终版本。模型自报会受宿主提示词、路由和训练先验影响；同一个请求别名也不能保证始终对应同一上游。

## 元数据与未知别名

- 非流式/流式响应、usage、`X-Magpie-Model` 均只出现 `chat-*` 别名，未见 `system_fingerprint` 或可验证的上游型号。
- 不存在的 `teleagent/*` 别名会回落默认后端并返回 200；响应中的 `model` 只是别名回显，不能证明该模型存在。
- 官方公开说明只写 TeleChat 语义模型，没有提供三档与具体版本的映射。

## 能否指定底层模型

**不能可靠指定。** 2026-11-13 又做了一组控制实验：

| 请求 model | math | Python | 法语 | 身份自报 |
|---|---|---|---|---|
| `glm-5.3` | `1024` | 闭式公式 | `Test d'empreinte de modèle` | `o3` / `无法提供该信息` |
| `glm-5.3-flash` | `1024` | 闭式公式 | `Test d'empreinte de modèle` | `GLM` |
| `glm-4.6` | `1024` | 闭式公式 | `Test d'empreinte du modèle` | `OpenAI o3` |
| `glm-does-not-exist` | `1024` | 闭式公式 | `Test d'empreinte du modèle` | `OpenAI o3` |

完全不存在的 `glm-does-not-exist` 与几个真实 GLM 名称在确定性输出上相同，说明这些名称并没有稳定切换到不同底层模型，而是进入了同一回退通道；身份自报本身又随请求变化。`model-options` 只列 `chat-*` 三个别名，带 `include_hidden` 等参数会被网关拒绝；引擎二进制里也没有别名到上游型号的映射。因此插件**不提供自定义底层模型选择**，避免把回退结果误标成某个真实模型。

## 对文档与 issue 的处理

保留“底层模型不可见”的表述，补充本次 50 次同题对照和版本自报不稳定的事实。**不新增别名到具体版本的映射，不把 GLM-4.6 或 GLM-5.3 写成确定版本。**
